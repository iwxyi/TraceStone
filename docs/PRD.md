### 1. 产品概述

#### 1.1 产品愿景
成为一个轻松、可信、长期陪伴的记录空间。用户可以自然写下生活，AI 在尊重事实和隐私的前提下，帮助用户理解自己、看见变化，并从过往经验中获得温和的成长线索。

#### 1.2 产品定位
一款以日记为起点、以长期记忆和个人化 AI 分析为核心、注重数据主权与隐私的跨平台记录与成长应用。

拾年不是打卡工具、任务管理工具或效率考核工具。它不要求用户每天完成目标，也不使用连续天数、完成率、成长评分来制造压力。成长来自长期记录后的自然看见，而不是每天被证明。

#### 1.3 目标用户
- 有持续记录习惯，但渴望从记录中获得深度洞察的人。
- 对个人成长有诉求，希望进行系统化自我认知的人。
- 注重隐私数据安全，希望数据完全由自己掌握的人。
- 愿意尝试用AI辅助反思，但抗拒空洞说教的人。

#### 1.4 核心价值主张
- **最懂你的AI记忆**：不是一次性分析，而是构建持续生长的个人认知模型。
- **原汁原味，绝不擅改**：修复错误，但永远保留你的语言风格和真情实感。
- **你的数据，你的主权**：支持WebDAV自建云备份、使用自己的AI Key，不绑架数据。
- **轻松成长，不做考核**：不给用户任务压力，不做打卡和完成率；只在合适时提醒“过去什么帮过你、这次有什么不同”。

### 2. 用户用例

#### 2.1 核心用户流程
1.  **自然记录**：打开App，进入建议记录日期的编辑页，含天气、地点等元数据；只有用户开始输入或保存时，才真正创建一篇日记实体。
2.  **轻松输入**：文本、语音或拍照。语音自动整理，图片自动压缩并识别情境。
3.  **智能修复**：保存时AI修正错别字和语病，保留原汁原味。
4.  **成长分析**：AI结合历史记忆，生成温和、个人化的读后感、历史回声、可复用经验和低压力的一小步。
5.  **成长线索**：用户可收藏 AI 提出的微小尝试，后续在日记中自然记录变化；它不是任务，也不需要打卡。
6.  **树洞问答**：在树洞与AI深度对话，获取基于个人历史的指引。
7.  **时光回看**：自动生成周/月/年总结，通过日历、列表等查看。
8.  **关系管理**：自动识别人际关系动态，支持自然语言查询。

#### 2.2 会员服务用例
- **免费用户**：每日3次AI日记分析，可使用基础成长线索。
- **拾年会员**：解锁更完整的成长分析、深度问答和周期总结能力。可使用自定义AI Key免费调用官方高级分析。

### 3. 功能需求详述

#### 3.1 日记创建与编辑模块
| 功能点 | 需求描述 | 优先级 |
| :--- | :--- | :--- |
| 建议日期打开 | 早晨打开默认进入“昨天”记录页；晚上打开默认进入“今天”记录页。仅创建编辑上下文，不自动生成空白日记实体。 | P0 |
| 多篇日记 | 同一天允许存在多篇日记。每篇日记使用独立 `entryId` 作为唯一主键；`date` 仅用于归档、检索与回顾展示。 | P0 |
| 自动元数据 | 通过IP或GPS获取天气、地理位置，自动填入。若用户手动修改，则后续不被自动定位结果覆盖。 | P0 |
| 语音输入 | 调用语音识别，完成后将口语化文本发送给AI，整理为通顺书面文字，保留原意和语气。 | P0 |
| 图片输入 | 支持拍照或相册多选。上传前客户端压缩。AI分析图片内容生成图说（如“傍晚，湖边，日落”）。 | P0 |
| 自动保存 | 默认自动保存为正式日记，不使用常规草稿模型。仅在异常崩溃场景下写入独立恢复快照。 | P0 |
| 崩溃恢复 | App 异常退出后，下次打开可提示恢复最近一次未完成编辑；恢复快照不参与正常读取、回顾或同步流程。 | P0 |
| 编辑模式隔离 | “新建模式”从空白开始；“编辑模式”只读取目标 `entryId`。两种模式的日期、内容、元数据不得互相继承。 | P0 |
| AI修复 | 保存时AI仅修正错别字、错误标点和明显语法不通之处，不改变用词、风格和句子长短。 | P0 |

#### 3.2 成长线索与微小变化记录（核心子模块）
*这是 AI 分析后的轻量承接模块。它不叫任务，不要求打卡，也不统计完成率；只收藏“可以轻轻尝试的一小步”，帮助用户在后续记录中看见变化。*

| 功能点 | 需求描述 | 优先级 |
| :--- | :--- | :--- |
| 线索生成 | AI分析日记后，输出一条低压力、可选择、可以轻轻尝试的一小步。 | P0 |
| 收藏线索 | 用户可收藏这一步，后续可编辑文字或删除；不设置强制截止日期。 | P0 |
| 线索列表 | 独立页面展示已收藏的成长线索和自然出现的变化记录。 | P0 |
| 变化记录 | 用户可写下“这次有什么不同”，也可以什么都不做；不使用打卡、连续天数或完成率。 | P1 |
| 历史关联 | AI在后续日记中，若识别到相关变化，会温和提及：“这可能和你之前收藏的一小步有关。” | P1 |
| 成长回看 | 在月/年总结中总结真实变化、可复用经验和仍需温柔留意的模式，不做完成统计。 | P1 |

#### 3.9.1 数据同步边界

拾年账号不承载日记云同步。账号后端仅负责登录、会员、额度、支付和必要聚合统计；日记正文、AI 分析、摘要、周期总结、用户画像、记忆和向量索引均不上传到账号后端。

跨设备备份与恢复统一由用户自己的 WebDAV 承载：

| 数据类型 | WebDAV 策略 | 账号后端策略 |
| :--- | :--- | :--- |
| 日记正文与元数据 | 以单篇 entry 文件备份 | 不上传 |
| 图片、音频等附件 | 作为媒体文件备份 | 不上传 |
| 单日摘要、分段摘要、关键词、人物、情绪 | 可作为 AI 衍生 JSON 备份 | 不上传 |
| 周/月/年总结 | 可备份，恢复后也可重建 | 不上传 |
| 用户画像、长期记忆、纪念日关联 | 可备份，恢复后允许重新生成 | 不上传 |
| 向量索引 | 默认不备份，模型变化后重建 | 不上传 |
| 主题、字体、显示偏好 | 可随 WebDAV 设置文件备份 | 不上传 |
| AI API Key、WebDAV 密码、日记锁密码、账号 token | 默认只保存在设备安全存储 | 不上传 |
| 日记数量、最后备份时间、额度消耗 | 不需要 WebDAV | 可上传聚合统计，不含明文 |

### 4. 技术架构与选型

- **客户端**：Flutter，承载所有UI、本地数据库、AI调用（直连第三方API）、WebDAV交互。
- **本地数据库**：ObjectBox（含向量检索），同时负责结构化数据和语义搜索。
- **向量嵌入模型**：通过 `EmbeddingService` 封装本地 embedding 模型，优先选择中文语义效果可靠、性能可接受的方案；模型取舍略偏向准确度，向量生成由后台队列串行执行。
- **语音识别**：平台原生API或第三方SDK。
- **图片压缩**：`flutter_image_compress`。
- **WebDAV**：`webdav_client` 库。
- **后端**：仅负责账号、计费、使用统计，不接触日记明文。

### 5. 交互与视觉风格
- **气质**：温润、沉静、有时间感。参考自然材质：石头、木头、纸张。
- **默认皮肤“溪石”**：暖灰背景，松石绿点缀，晨昏渐变（淡紫、橘粉）。
- **动效**：柔和、缓慢，如水流或书页翻动。加载动画为石头被水打磨的微动效。
- **字体**：中文宋体或楷体，英文衬线体，强化书卷气。
