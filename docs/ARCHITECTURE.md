# 拾年·Shinen 技术架构

## 架构原则

| 原则 | 说明 |
| --- | --- |
| 本地优先 | 日记、记忆、向量索引优先在端侧保存和检索 |
| 明文不上云 | 后端只处理账号、计费、额度，不接触日记明文 |
| AI 可替换 | 官方额度和用户自定义 Key 共存 |
| 离线可用 | 无网络时编辑、搜索、时光等本地能力仍可用 |
| 模块隔离 | 日记、洞察、成长线索、树洞、搜索、关系、设置独立演进 |
| 低压力体验 | 面向用户不设计打卡、任务、连续天数和完成率；后台队列只作为整理进度呈现 |

## 分层结构

| 层 | 职责 | 例子 |
| --- | --- | --- |
| Presentation | 页面、组件、交互状态 | 日记编辑页、成长线索页 |
| Application | 用例编排、权限检查、状态流转 | 保存日记、生成洞察、收藏成长线索 |
| Domain | 业务实体和规则 | DiaryEntry、StoneTask、MemoryShard |
| Data | 数据访问与外部服务适配 | ObjectBox、WebDAV、AI Client |

## 核心数据流

### 保存日记

```text
编辑输入
  ↓
草稿自动保存
  ↓
保存日记
  ↓
AI 原汁原味修复
  ↓
本地写入 DiaryEntry
  ↓
生成今日分析与成长线索
  ↓
更新记忆库、标签、人物、向量索引
```

### 语义搜索

```text
自然语言查询
  ↓
TFLite 本地嵌入模型生成 384 维向量
  ↓
ObjectBox Vector Search
  ↓
按时间、情绪、标签、图片等筛选
  ↓
返回相关日记、总结、人物互动
```

### WebDAV 备份

```text
本地数据快照
  ↓
Markdown + JSON + 媒体资源打包
  ↓
用户配置的 WebDAV 目录
  ↓
恢复时重建 ObjectBox 数据和向量索引
```

WebDAV 是日记与 AI 衍生数据的唯一跨设备备份/恢复通道。备份文件建议按可读性和可恢复性分层：

| 目录 | 内容 | 默认策略 |
| --- | --- | --- |
| `entries/` | 单篇日记 Markdown 与 JSON 元数据 | 必备 |
| `media/` | 日记图片、音频等附件 | 必备 |
| `ai/daily/` | 单日日记摘要、分段摘要、关键词、情绪、人物 | 可备份 |
| `ai/period/` | 周/月/年总结 | 可备份 |
| `ai/memory/` | 用户画像、长期记忆、纪念日关联 | 可备份，恢复后允许重新生成 |
| `ai/vector/` | 向量索引缓存 | 默认不备份，模型变化后重建 |
| `settings/` | 主题、字体、显示偏好、非敏感 AI 配置 | 可备份 |

敏感设置不写入普通 WebDAV 配置文件：AI API Key、WebDAV 密码/token、日记锁密码、账号 JWT 只保存在设备安全存储。后续如要备份这些内容，必须先做用户主密码加密包。

### 导入导出

手动导入导出服务于迁移和归档，不替代 WebDAV 同步。WebDAV 负责拾年自己的完整备份恢复；导入导出负责接收其他日记软件或用户自有文档。

常见来源格式分为几类：

| 类型 | 常见形态 | 拾年策略 |
| --- | --- | --- |
| 文本 | 日期标题 + 正文，日期可能是 `2026.01.01`、`2026年1月1日`、`【2026.01.01】`、`01.01`、`# 2026.01.01` 等 | MVP 支持模板预设、可编辑正则、预览后导入；Markdown 标题只是文本模板之一，只有带日期的标题才会切分日记 |
| 结构化 JSON/ZIP | Day One、Diarium、Journey 等常用于完整迁移，可能包含 media、tags、location、weather | 后续按来源适配器解析，优先保留正文、日期、标题、标签和媒体引用 |
| CSV | 常见于轻量导出或统计型日记，通常包含 date/text，也可能包含 mood、tag、weather 等列 | 后续提供列映射界面 |
| Word/HTML | Diarium、Journey 等支持，内容可读但结构和附件引用差异大 | 后续转 HTML/文本解析，必要时提示用户先导出 JSON/Markdown |
| PDF | 适合阅读归档，不适合无损迁移 | 后续只作为辅助导入，需明确可能丢失结构和附件 |

文本导入要求每篇日记有可识别的日期标题。正则表达式使用命名分组：`year` 可选，`month` 和 `day` 必需，`title` 可选。无年份文本需要用户填写起始年份；当月份从大变小时，系统自动推断跨入下一年。确认导入后逐篇保存 DiaryEntry，并统一进入 AI 整理队列。

导出首版支持拾年文本和 JSON。拾年文本面向阅读与二次导入；JSON 保留完整字段，适合备份、迁移和开发检查。导出文件是明文，包含私人内容，保存位置由用户选择。

导入导出必须按大数据量设计。几千篇日记导入时，文件读取优先使用流式读取；预览列表必须虚拟化，不能一次构建所有卡片；确认导入必须走批量保存、批量队列入队和批量周期总结状态标记，避免每篇日记都触发全量日记扫描、导航刷新或队列刷新。后台 AI 整理仍保持统一队列串行执行，避免导入后并行压垮模型接口。

### 账号登录

```text
手机号验证码 / 密码登录
  ↓
后端签发 App 用户 JWT（appId=1003）
  ↓
flutter_secure_storage 保存 token
  ↓
“我”页面进入账号页
  ↓
读取账号资料与会员状态
```

账号体系只服务登录、会员、额度和支付。日记明文、记忆库、向量索引和 AI 调试数据不通过账号接口上传；日记备份与恢复只走用户自己配置的 WebDAV。

### 日记锁

```text
设置页选择 PIN / 独立密码 / 系统认证
  ↓
flutter_secure_storage 保存锁配置
  ↓
PIN / 密码只保存加盐哈希
  ↓
App 启动或从后台恢复时按锁定时机要求解锁
```

日记锁是本机保护层，不等同于账号登录。账号用于会员和额度，日记锁用于确认当前持有设备的人可以查看本机日记。生物识别通过 `local_auth` 调用系统认证，不直接读取指纹或面容数据。

## 关键模块边界

| 模块 | 输入 | 输出 |
| --- | --- | --- |
| Diary | 文本、语音文本、图片、天气位置 | DiaryEntry、Draft、Attachment |
| AI Insight | DiaryEntry、Memory Context | 修复文本、洞察、摘要、标签、成长线索 |
| Growth Cues | AI 建议、用户编辑 | 低压力的一小步、微小变化记录 |
| Tree Hole | 用户问题、检索到的记忆 | 引用历史的回答、引导式追问 |
| Time | 周/月/年日记、成长线索 | 周报、月报、年报、真实变化回看 |
| Search | 查询文本、筛选条件 | 语义匹配结果 |
| Relationships | 日记实体识别结果 | 人物档案、互动记录、关系查询回答 |
| Account | 手机号、验证码、JWT | 登录状态、账号资料、会员状态 |
| App Lock | PIN、独立密码、系统认证结果 | 本机解锁状态 |
| Settings | 用户配置 | 主题、安全、备份、AI 设置 |

## 后端边界

| 能做 | 不能做 |
| --- | --- |
| 账号登录 | 存储日记明文 |
| 会员状态 | 读取用户记忆库 |
| 使用额度统计 | 训练用户私有数据 |
| 支付回调 | 替用户托管 WebDAV 明文数据 |
| 日记数量/备份时间等聚合统计 | 上传日记、摘要、总结、画像、向量 |

日记同步边界：账号后端不做日记云同步，不保存用户日记、摘要、向量、记忆或 AI 调试记录。需要跨设备迁移时，只使用 WebDAV 备份恢复能力。
